# 一致性承诺与重试条件

## 一致性承诺

1. 单页快照内部一致：一次领取中，请求的正文修订、实际展开结果、依赖断言取自同一 oldid 的同一次 parse 响应；三者分别保存，正文与展开的原始字节各自归档，摘要可核对。展开与请求的正文修订对不上时按失败处理。
2. 内容版本只由正文修订与已证明依赖修订决定（content_key）。分类等附属信息变化不产生新内容版本，普通分类变化不会触发重新领取。
3. 不承诺全站同一时刻：领取期间来源可能更新共享模板，不同页面记录各自实际用到的依赖修订，报告按页呈现实际使用的展开结果。
4. 来源给不出依赖修订时记为无法证明（unversioned），该页一致性降为部分证明；增量扫描无法核对这类依赖的新鲜度，单列说明。绝不拿随后查到的最新修订补成伪快照。
5. 展开失败只追加失败尝试记录，不替换当前可用内容。

## 有限重试条件

- 仅重试可能瞬时的失败：传输错误与 HTTP 429/5xx。最多 2 次重试（共 3 次尝试），间隔随次数递增。
- 其余 4xx（404 不存在或已删除、403 权限不足等）属于确定性状态，立即失败，不重试。
- 重试耗尽后记录失败尝试（含状态码与请求路径），页面继续提供上次可用内容。

## 运营区分

- 正文变化：最近变化为“正文变化”（正文修订号变化）。
- 依赖变化：最近变化为“依赖变化”（正文修订不变、已证明依赖修订变化）——即“同一修订号看到不同参数”的情形。
- 来源无法提供稳定展开：一致性为“部分证明”（存在无法证明/循环/权限不足/已删除依赖），或最近领取有失败尝试。
